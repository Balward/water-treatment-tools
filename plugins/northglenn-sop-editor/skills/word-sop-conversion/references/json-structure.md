# SOP Creator schema (confirmed from the app)

Snapshot: `apps/sop-creator/model.js`, November 9, 2026. Executable validator: `../scripts/sop-model.cjs`. Check against a newer app model when available. A successful parse alone is not schema validation.

Root: `{ "format": "northglenn-sop", "version": 1, "document": { ... } }`.

The document contains:

- `id`: unique alphanumeric/hyphen ID (UUID recommended), `revision`: nonnegative integer; a converted/imported document starts at zero.
- Strings: `title`, `team`, `effectiveDate`, `preparedBy`, `approvedBy`, `purpose`, `background`, `notes`, `safety`, `security`, `equipment`. Empty strings are valid for metadata absent from the source. Dates must be empty or exact valid `YYYY-MM-DD`; do not invent a day for a month-only source date.
- `tags`: zero to 20 distinct tags from the validator's curated list; do not infer tags unless requested.
- `revisionHistory`: entries `{id,type,date,summary,revisedBy,approvedBy}` with type `creation`, `revision`, or `review`. Keep empty if the source has no actual history. Conversion is not a new technical revision and must not invent a new approval or creation event.
- `groups`: ordered `{id,title,steps}` objects; the default untitled group has an empty string title.
- Each step: `{id,instruction,substeps,photos,tables}`. No separate step title is needed. Each substep: `{id,text}`. Preserve numbers in instruction text when they are operational references; list numbering itself is generated by the app.
- Each table: `{id,caption,headers,rows}`; 1–8 headers, 1–50 body rows, equal-width string arrays, at most six tables per step.
- Each photo: `{id,data,caption,scale}`. `scale` is optional, integer 25–200; default 100. `caption` is a string, at most 1,000 characters.

Photo data must be a complete Base64 **data URL**:

```text
data:image/png;base64,<actual complete encoded image bytes>
data:image/jpeg;base64,<actual complete encoded image bytes>
data:image/webp;base64,<actual complete encoded image bytes>
```

These examples show syntax only; angle-bracket placeholders are never valid output. Image type must match actual bytes. The app rejects SVG, remote URLs, file paths, and bare Base64 without the MIME prefix. Use at most eight photos per step, 3,000,000 characters per data URL, and 12,000,000 total data-URL characters per SOP. Do not truncate Base64 to fit.

Other limits: 30 groups, 200 steps, 26 substeps per step, 100 history entries. IDs must be unique across document, groups, steps, substeps, photos, tables, and history. The validator enforces string lengths. It normalizes documents and drops unknown keys, so **do not run it to rewrite an existing JSON backup**: preserve the original object and use normalization only as a separate validation check for the existing-JSON workflow.
