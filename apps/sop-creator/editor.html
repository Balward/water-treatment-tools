How to Write an SOP

Write for a trained operator performing the task for the first time. Make the sequence clear, the actions specific, and the expected results easy to check.

Use Direct, Action-Based Language

Start instructions with a verb: Inspect, Close, Select, Measure, Record, or Verify. The operator is the implied subject. Avoid first person (I, we), second person (you), and third-person narration (the operator, he, she, they).

Instead of: “I then check the probe for damage.”

Write: “Inspect the probe for damage.”

Instead of: “The operator should write down the result.”

Write: “Record the result in the calibration log.”

Use present tense and plain words. Replace vague instructions such as “check that it looks good” with the specific condition to verify. Name the equipment instead of using an unclear “it.” Identify a responsible role when assigning work to someone else: “Notify the shift supervisor.”

Set Up the Document

  • Title: Use Equipment or Process — Task, such as “pH Probe (DPD1P1) — Calibration.” Keep dates and “SOP” out of the title.
  • Responsible Team: Select the team that maintains the procedure.
  • Tags: Choose relevant equipment, process, and task tags, such as pH, Calibration, and Instrumentation.

Give Each Context Field a Job

  • Purpose: State what the procedure accomplishes and its scope in one or two sentences. Example: “Describe the process for calibrating the DPD1P1 pH probe.”
  • Background: Explain essential context or why the task is needed. Keep operating actions in the steps. Leave this field empty when it adds no useful context.
  • Equipment: List required tools, materials, and reference documents, one item per line.
  • Safety Concerns: Identify relevant hazards, required PPE, and precautions before starting. Repeat critical precautions in the step where they apply.
  • Security Concerns: Describe applicable access restrictions or security precautions.
  • Notes: Add useful supporting information that does not belong in a numbered action.

Leave unused fields empty. The creator omits empty context sections from the document.

Divide the Procedure Into Sections

Use Add Section for meaningful phases, such as Preparation, Calibration, and Return to Service. Use short descriptive headings. A short procedure may need only one section, with its heading left blank. Step numbering continues automatically across sections.

Write Steps and Substeps

Give each numbered step one main action or a closely related task. Put actions in the order they must occur. Include the equipment or control name, required value and unit, expected result, and where to record the result when applicable.

Use lettered substeps for smaller actions that belong to the parent step. For example, “Inspect the probe assembly” can contain “Inspect the cable for damage” and “Inspect the connector for corrosion.” Use a new numbered step when the main task changes. Avoid placing an unrelated phase inside a substep.

State conditions explicitly: “If [condition], [action].” Describe what to do when a required check fails, including when to stop and who to notify. Keep required actions out of general Notes.

Do not type step numbers or substep letters into instructions. The creator supplies them. Enter creates the next item; Shift+Enter inserts a line break. Use Add Substep to group supporting actions beneath a step.

Use Photos and Tables Where They Help

Attach photos to the step they explain. Add a short caption identifying the control, connection, or condition shown. Keep the written instructions complete enough to use without interpreting a photo alone.

Use a table for repeated comparisons, reference values, or several related readings. Include units in column headings and a caption when needed. Enter content in the table cells instead of aligning text with spaces.

Review and Record the Change

Walk through the draft with an operator familiar with the task. Check equipment names, sequence, units, limits, warnings, and the return-to-service actions against current facility requirements and manufacturer instructions. Do not guess missing technical details.

In Revision History, use Creation for the original procedure, Revision for changes, or Review - No Changes when checking an unchanged procedure. Record the date, the person who performed the work, and an accurate summary. Record an approver only after approval actually occurs. Keep historical names when staff change; the Responsible Team maintains the SOP.

Check the Live Preview and Print / Save PDF before saving. The creator keeps context, sections, steps, substeps, photos, tables, and history in separate fields, so use those fields rather than pasting the entire SOP into one instruction box.
